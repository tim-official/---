# Матрица судьбы — 10 секунд

Отдельный видеопроект: вертикальный ролик 1080 × 1920, 60 кадров/с,
H.264 / AAC. Сайт, его backend и зависимости не изменяются.

## Материалы

- `matrix-destiny-10s.mp4` — итоговый ролик после сборки.
- `poster.png` — обложка, извлечённая из готового видео.
- `scene.html` / `scene.js` — оригинальная анимация Canvas; HTML можно открыть
  локально для просмотра без звука.
- `audio/` — записи согласованного текста голосом `ru-RU-DmitryNeural`.
- `audio/master.wav` — полная звуковая дорожка с оригинальной музыкой.
- `narration.json` — фактические границы фраз после удаления внешней тишины.
- `verification.json` — результаты проверки итогового файла.

Числа в иллюстрации декоративные: это не персональный расчёт и не обещание
каких-либо результатов. Музыкальная атмосфера и звуки созданы локально,
без скачанных музыкальных произведений. Используются установленные в Windows
Georgia и Segoe UI; сами шрифты не распространяются.

## Повторная сборка

Запускать в PowerShell из корня репозитория. Используются отдельное окружение
`.tools\matrix-video` и уже установленный `@playwright/test` в пользовательской
папке npm. Рендерер не устанавливает пакеты и запускает изолированный Chromium
без сети, пользовательского профиля и cookies.

```powershell
$python = '.\.tools\matrix-video\Scripts\python.exe'
$project = '.\media\matrix-destiny-10s'

node "$project\render.mjs" stills
node "$project\render.mjs" frames
& $python -I -B -X utf8 "$project\audio.py" mix
& $python -I -B -X utf8 "$project\encode.py"
& $python -I -B -X utf8 "$project\verify.py"
```

Промежуточные кадры сохраняются только в игнорируемую папку
`.tools\matrix-video-work`. WAV остаётся рядом с записями для проверки
и повторного монтажа. Повторный рендер перезаписывает результаты
этого видеопроекта. Готовые записи речи повторно используются офлайн.
Отсутствующая или слишком длинная запись вызывает ошибку, а не тихую подмену.

## Озвучка: отдельное сетевое действие

Текст: «Матрица судьбы. Твоя дата. Твой путь. Открой себя с новой стороны».
Только следующая явно запущенная команда отправляет отсутствующие фразы
сервису Microsoft; исходники и другие файлы не отправляются:

```powershell
& $python -I -B -X utf8 "$project\audio.py" narrate
```

`edge-tts` — неофициальный клиент, не Azure Speech API с гарантией доступности.
Сервис может не вернуть аудио; ошибка выводится явно, автоматических повторов
или замены голоса нет. Успешные записи проверяются перед сохранением, поэтому
после временного сбоя можно повторить команду, сохранив уже записанные фразы.

## Зависимости и проверки

`requirements.txt` содержит три прямые зависимости, `requirements-lock.txt` —
16 точных версий и SHA-256 колёс для Windows x64 / CPython 3.14.
Для первоначальной установки колёса сверены с PyPI, проверены на опасные
пути/автозагрузку и просканированы Microsoft Defender без обнаруженных угроз;
известные GitHub-reviewed advisories для выбранных версий не найдены
на момент проверки. Это не гарантия отсутствия всех уязвимостей.

Основные источники:
[PyAV](https://github.com/PyAV-Org/PyAV),
[edge-tts](https://github.com/rany2/edge-tts/tree/360fa8e1de354e1dda74c09bd695887d6a44df74),
[NumPy](https://github.com/numpy/numpy).

Рендер проверяет безопасные поля текста, отсутствие ошибок/сетевых запросов
и воспроизводимость кадров. Проверка MP4 декодирует все 600 кадров,
проверяет 10 секунд, 1080 × 1920, 60 fps, кодеки, метки цвета BT.709
(ограниченный диапазон), присутствие всех трёх голосовых фрагментов,
уровни звука и обложку. Пять кадров и обложка сравниваются с lossless-кадрами
из `.tools\matrix-video-work\stills`: PSNR выше 32 дБ и сдвиг среднего
цвета меньше 1,5 уровня, поэтому `render.mjs stills` нужен перед `verify.py`.
Дополнительно сверяются подтверждённый сервисом текст всех фраз и корреляция
декодированной дорожки с полным исходным WAV: голос не должен быть обрезан
или потерян при кодировании.

JPEG-кадры имеют полный диапазон BT.601. Кодировщик сначала точно переводит
их в RGB, затем в BT.709 с ограниченным диапазоном: прямое YUV → YUV
преобразование затемняло ролик примерно на 12 уровней, а быстрый путь
swscale сдвигал тёмно-зелёный фон в синий.
Кадры читаются последовательно одним декодером; два потока x264 и ограниченный
lookahead уменьшают потребление памяти. CRF 18 с ограничением 20 Мбит/с
(буфер 40 Мбит) даёт файл около 27 МБ вместо ~260 МБ без ограничения;
слегка сглаживается только едва заметное статичное зерно.
